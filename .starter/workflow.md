# Task-Ayuza: общий процесс для Claude Code и Codex

Основа: шаблон artemiimillier/claude-code-starter, адаптирован под Task-Ayuza.
Источник правил для обоих агентов. CLAUDE.md и AGENTS.md только ссылаются сюда.

## 0. Приоритет документов
1. Прямая команда владельца в чате.
2. AGENTS.md и PROJECT_STATUS.md (локальные правила проекта сохраняются).
3. ТЗ 2.2 (согласованная бизнес-логика не меняется без команды владельца).
4. Этот файл.
При конфликте требований агент не выбирает сам, а явно сообщает владельцу, какие пункты расходятся.

## 1. Старт задачи
- Прочитать запрос, PROJECT_STATUS.md, активный план в `plans/` и последний checkpoint.
- Читать только файлы, нужные для задачи (экономия токенов).
- Определить текущее состояние: идея, архитектура, код или незавершённая работа. Продолжать с него, без повторного онбординга.
- Спрашивать только о пробелах, которые меняют следующее решение. Остальное решать самостоятельно.

## 2. Контекст и приватность
- Бизнес-контекст хранится в `.business/INDEX.md` (вне git). Факты и гипотезы разделяются.
- Пароли, токены, ключи, персональные данные в репозиторий и в контекст агента не попадают. Пароль PostgreSQL хранится вне репозитория.
- `.gitignore` не защищает уже отслеживаемые файлы: перед публикацией проверять staged diff и историю.
- Зарубежные сервисы только для тестов на синтетических данных.

## 3. Архитектура и план
- Один канонический документ архитектуры. Существующие планы дополняются, а не дублируются.
- Первая фаза новой функции: минимальный сквозной пользовательский сценарий (MVP с демо).
- План пишется по `plans/TEMPLATE.md`: фазы, критерии приёмки, проверки, лимиты.
- Независимый аудит плана и результата делает ChatGPT (роль архитектора и аудитора). Финальный план утверждает владелец.
- При работе через GitHub статус ветки хранится в Issue/PR; `plans/` дополняет их локальным планом и checkpoints, но не заменяет.

## 4. Исполнение
Работа идёт атомарными задачами по правилам AGENTS.md (Issue, ветка, Draft PR). План покрывает только фазы, на которые есть разрешение владельца. Цикл каждой фазы:
1. Тест, который сначала падает.
2. Реализация.
3. Рефакторинг.
4. Проверки: тесты (pytest), compileall, `git diff --check`, проверка безопасности и регрессии.
5. Независимое ревью, исправление принятых замечаний.
6. Проверка интегрированного состояния и checkpoint в плане с реальными результатами.

Лимиты времени, расходов и повторов задаются заранее. Агент останавливается при блокере, исчерпании лимита или необходимости новых прав.

## 5. Полномочия
Без отдельного прямого разрешения владельца запрещено:
- деплой и любые действия в production;
- push в GitHub, merge, публикация PR;
- платные действия и подключение платных сервисов;
- production-миграции, удаление данных, изменение DNS и секретов.

Также запрещено включать bypass-режимы, ослаблять sandbox и hooks.
Чужие несохранённые правки владельца (например, в `tests/`) не трогать без команды.
Коммиты только в рамках согласованной задачи, в своей ветке по правилам AGENTS.md, не в main.

## 6. Завершение

- Финальный отчёт по формату раздела «Проверки и завершение» AGENTS.md: что работает, чем проверено, что осталось, одна следующая задача. Без преувеличения результатов.
- Указать, в каком инструменте (Claude чат или Claude Code) и на какой модели делать следующий шаг, и дать текст для продолжения в новом чате.
- Записать урок в `retrospectives/`, если он пригодится в будущих задачах.
