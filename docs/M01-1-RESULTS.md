## Исправления

- A07: `OrganizationAlreadyExistsError` с фиксированным безопасным сообщением, только для SQLSTATE `23505` и точного сочетания schema/table/constraint `task_ayuza.organization.organization_singleton_key_key`. Другие IntegrityError пробрасываются без подмены. Вызывающая сторона обязана откатить транзакцию; тест использует `session.begin()`. API в M01.1 не добавлен.
- A04/A05/A09: запреты прав проверяются по `42501`, а не по любой ошибке. A06/A08 проверяют `23514` и конкретный CHECK.
- JSONB: оба CHECK явно требуют ключ `name`, поэтому `{}` больше не проходит через SQL NULL. ORM и начальная миграция изменены одинаково. Шесть негативных случаев: old/new × `{}`, `{"name":null}`, `{"name":""}`; каждый проверен в Python и PostgreSQL.
- Конкурентный и последовательный повтор проверяют прикладную ошибку, сохранность победителя и отсутствие лишнего события. Четыре unit-сценария подтверждают проброс посторонних ошибок (другой SQLSTATE, constraint, schema, table).

Начальная ревизия исправлена до интеграции, в рамках требования одной начальной миграции. Прогон выполнен только на новых БД. Повторный upgrade уже созданной старой БД не обновит CHECK: такой одноразовый контур надо пересоздать. Существующие/рабочие БД не затрагивались.
