## Границы и решения

Разрешение владельца и точные B1–B2 зафиксированы в Issue #10. Проверены AGENTS.md,
PROJECT_STATUS.md, M01-CODEX-TASK.md §§1, 4–6, TZ-2.2 §§3, 15, 17 и модель users/sessions,
аудита и транзакционной проверки доступа. Конфликтов утверждённых параметров не выявлено.
Устаревшая карточка PREP заменяется в этой ветке; новое поручение владельца разрешает реализацию.

- Миграция 0002 добавляет users, sessions (в том числе prelogin/password), login_attempts,
  ограничения и адресное расширение аудита. 0001 не изменена. В auth-аудите old/new всегда NULL.
- Логин проверяется как ASCII **до** lowercase, trim только у логина. UNIQUE включает неактивных.
- Argon2id: 65536 KiB, t=3, p=1, salt=16, hash=32. Пароли 15–128 Unicode code points,
  без trim/Unicode-нормализации/периодической смены. Проверка blocklist локальная, casefold только
  для сопоставления с blocklist; хешируется исходный пароль. Unicode surrogate отклоняется.
- Временный пароль: 18 случайных байт → 24 base64url, 24 часа. Ограниченная сессия:
  min(10 минут, остаток срока пароля). Смена отзывает все сессии и требует новый вход.
- Обычная сессия: idle 30 минут, absolute 8 часов; GET /me не продлевает. POST /renew
  применяется только по явному действию клиента, не включать его в фоновый polling.
  Токен 32 случайных байта → base64url; в БД SHA-256, продление без ротации.
- Logout отзывает текущую сессию. Смена/сброс/деактивация повышают auth_version и отзывают
  все сессии в одной транзакции с аудитом.
- CSRF: отдельные 32 случайных байта, в сессии хеш; X-CSRF-Token на каждой мутации.
  Origin сравнивается точно; Referer используется только при отсутствии Origin;
  отсутствие обоих отклоняется. Prelogin живёт 10 минут и удаляется при успешном входе.
- Cookie __Host-ay_session: Secure, HttpOnly, SameSite=Lax, Path=/, без Domain.
  no-store также на отказах/валидации. Ответы валидации не включают исходные данные.
- Ограничитель: HMAC-SHA256 ключи login/IP; полный ключ в счётчике, упорядоченные advisory
  locks сериализуют оба лимита. 5/login, 100/IP, скользящие 15 минут, резервирование до Argon2
  фиксируется отдельной транзакцией. Успех/рестарт не сбрасывают счётчик. Неизвестный аккаунт
  проходит dummy Argon2 после лимита; ошибка одинакова с неверным паролем/неактивным аккаунтом.
- Порядок user → session; удержание блокировок до завершения защищённого callback и commit.
  Отзыв, сериализованный первым, запрещает последующую операцию; ранее сериализованная операция
  может завершиться. Максимум 2 повтора 40P01/40001; аудит откатывается вместе с транзакцией.
- Закрытый maintenance удаляет попытки спустя 24 часа после окончания 15-минутного окна,
  сессии спустя 24 часа после истечения/отзыва. Аудит не удаляется. Команда:
  `python -m backend.auth_maintenance`. Планировщик нужно настроить при отдельно разрешённом
  деплое; в этой задаче он не устанавливался. Импорт/startup не выполняют очистку, seed или DDL.

## HTTP-контракт

| Маршрут | Назначение |
|---|---|
| GET /api/v1/auth/prelogin | Same-origin bootstrap cookie/CSRF |
| POST /api/v1/auth/login | Вход, замена и уничтожение prelogin |
| GET /api/v1/auth/me | Проверка обычной сессии, без продления |
| POST /api/v1/auth/renew | Продление в пределах absolute, тот же токен |
| POST /api/v1/auth/logout | Отзыв текущей сессии, очистка cookie |
| POST /api/v1/auth/password | Смена пароля, отзыв всех сессий, очистка cookie |

Нет публичной регистрации, создания/сброса/деактивации пользователей или административного API.
Внутренние create_user/reset_password/deactivate не являются проверкой полномочий M01.4;
подключать их к HTTP до MFA/ACL запрещено. /me не открывает рабочие полномочия.

кластер в TemporaryDirectory с проверкой data_directory, пустой БД и listen_addresses.

## Пробелы и передача

Независимая PostgreSQL-приёмка TEST-10-PG-RUN выполнена (выше); независимого ревью кода в ChatGPT пока нет. Не выполнены production-нагрузка, полный аудит уязвимостей
всех транзитивных зависимостей, браузерная/PWA-приёмка, MFA/ACL, backup/restore, F01–F37.
Blocklist конечный; обновление корпуса отдельно, без внешней проверки пользовательских паролей.
Bootstrap prelogin не имеет отдельного инфраструктурного лимита; настройки edge/body/concurrency
limits проверять до production. Не объявлять эту ветку готовой к публикации.

Для реального запуска требуются стабильный HMAC-ключ вне Git, точный HTTPS origin,
TLS и корректный доверенный источник IP. Тестовый сервер/прямой Uvicorn запускается с
`--no-proxy-headers`; заголовки X-Forwarded-For напрямую приложение не читает. Настройка
доверенного reverse proxy и планировщика cleanup относятся к отдельно разрешаемому деплою.
При смене HMAC-ключа нельзя обходить действующие окна лимита; автоматическая ротация не реализована.
