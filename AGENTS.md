# Task-Ayuza | Правила Codex
Адаптация стандарта v1.2. Основной исполнитель разработки и тестов: ChatGPT Codex. Другой исполнитель только по отдельному назначению владельца.

## Контекст
- Одна атомарная задача = одна рабочая сессия. Начни с [PROJECT_STATUS.md](PROJECT_STATUS.md): факты и единственная карточка следующей задачи. Сверь её с поручением, веткой и ревизией; карточка сама не разрешает начать следующий этап.
- Примени этот файл один раз. Не перечитывай уже загруженные актуальные инструкции; при смене ветки, SHA или утрате контекста проверь изменения и загрузи только недостающее. В новом чате проверяй актуальные источники, не полагайся на память.
- Затем читай указанные разделы, необходимые зависимости, контракты, общие ограничения и тесты. Сначала поиск по пути/заголовку/ID, затем нужный диапазон. Полный файл или лог только при обоснованной необходимости.
- [PROJECT.md](PROJECT.md): паспорт, карта документов и исторический аудит; [ТЗ 2.2](docs/TZ-2.2.md): требования/F01–F37; [модель](docs/DATA-MODEL-ACCESS-2.2.md): D01–D06 и детализация. Их не загружать целиком по умолчанию.
- Правила Git и передачи ниже обязательны; [регламент](docs/AI-COLLABORATION.md) нужен при передаче авторства, конфликте или настройке процесса. Дополнительное чтение не расширяет право правки.
- Недоступные, устаревшие и противоречивые источники обозначай явно. Действующие решения Task-Ayuza важнее универсального шаблона; бизнес-логику самостоятельно не меняй.

## Ограничения
- Бюджет строго 0 ₽: бесплатные open-source решения, законные инструменты, API и инфраструктура. Платные зависимости/подписки запрещены; отсутствие бесплатного безопасного решения фиксируй блокером.
- Web/PWA, одна компания, PostgreSQL, сервер и рабочие данные в РФ; FastAPI/SQLAlchemy/HTML/CSS/JS. Без интеграции Sol Flow.
- GitHub только для кода, документации и CI. Не коммить секреты, реальный .env, ПДн, рабочие записи, дампы и аудио. Соблюдай лицензии и 152-ФЗ.
- Не ослабляй HTTPS, авторизацию, серверные RBAC/ACL, аудит, резервирование и проверку восстановления. Утверждённые функции, этапы и D01–D06 сохраняются в канонических документах.
- Анализ по умолчанию read-only. Код и тесты только в разрешённых границах; расходы, доступы, удаление данных, миграции и production/деплой требуют явного разрешения. Учитывай уже выданное разрешение в его точных пределах.
- Перед правками: краткая цель, границы, приёмка; актуальные main, Issue и открытые PR, проверка пересечения файлов/контрактов. Один Issue, один автор, одна ветка, один PR. Не пиши в чужую ветку или напрямую в main.
- Ветка от свежего main: codex/<issue>-<slug> или docs/<issue>-<slug>. PR сначала Draft; после обязательных проверок Ready. Merge только после ревью, проверок, отсутствия конфликтов и явного решения владельца; без auto-merge и force-push.
- При пересечении работ останови запись, согласуй последовательность/автора в Issue/PR. Передачу авторства фиксируй там до правок.

## Проверки и завершение
- Минимальный diff, без лишних зависимостей/рефакторинга. Целевые позитивные/негативные проверки, права и регрессии затронутой логики; полный прогон на интеграционных контрольных точках. Для документации проверяй ссылки, согласованность и границы diff.
- Повторяй проверки после изменений или при новой причине; не запускай бесконечные циклы. Чужие отчёты отделяй от своих проверок.
- Статус ветки и детали продолжения храни в Issue/PR. PROJECT_STATUS.md обновляет один назначенный автор через PR; main отражает только интегрированные факты. Не выдавай предложенное за слитое. PROJECT.md не накапливает хронику.
- Финал каждой сессии: результат; проверки и пробелы; файлы; блокеры; статус; одна следующая задача; рекомендуемые режим, модель ChatGPT и уровень мышления с краткой причиной; полный готовый промпт нового чата. Следующую задачу не начинай автоматически.
- Для кода рекомендуй Codex с доступной моделью; для обычного ревью средний уровень мышления, для архитектуры/БД/безопасности высокий. Называй модель, но не утверждай её доступность без проверки; при отсутствии предложенной модели выбирай доступный аналог.
- Промпт: репозиторий, ID/цель, ветка/PR, разрешения/запреты; применить AGENTS без повторного чтения, сверить карточку PROJECT_STATUS, прочитать нужные разделы/Issue/PR, выполнить приёмку и завершить по этому правилу. Без переписки и копии ТЗ.
