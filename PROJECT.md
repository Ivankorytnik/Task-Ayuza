# PROJECT.md | Task-Ayuza

**База требований:** согласованное ТЗ 2.2 (11.11.2026). **Режим работы:** ChatGPT Web → «Работа» (управление), Codex (код и тесты). **Ограничение:** без деплоя без разрешения.

## Цель и границы
Внутренний многопользовательский трекер одной компании: web/PWA на ПК, Android и iPhone; общая PostgreSQL; сервер/данные в РФ. Только бесплатные open-source компоненты; GitHub — код и CI, без рабочих данных и секретов. Без Sol Flow, платных API и автосоздания задач.

## Инварианты ТЗ 2.2
- Пользователи, роли/RBAC; проекты и задачи «Без проекта»; подзадачи и комментарии.
- Команда/отдел-исполнитель, персональный исполнитель, владелец результата; «Мои задачи», «Зависимые задачи».
- Статусы, приоритеты, сроки, связи/зависимости, блокеры, история закрытия и переоткрытия.
- Список, Kanban, Gantt, календарь, поиск/фильтры, аналитика, уведомления, экспорт.
- Отдельный «Центр рисков» по платформе: юридические/ПДн, безопасность, сервер, резервирование, качество и организационные риски; подтверждаемые проверки и светофор.
- Голосовое создание только через локальное распознавание (вариант: whisper.cpp), проверку/редактирование текста и ручное подтверждение.
- Строгий современный адаптивный UI, светлая/тёмная темы; фактическая версия и дата/время публикации в правом верхнем углу.
- HTTPS, аудит, серверное разграничение доступа, резервное копирование/восстановление и соблюдение 152-ФЗ.

### Существенные риски и повторное использование
Приоритет означает важность устранения перед пилотом, а не подтверждённую эксплуатацию уязвимости.
- **Высокий, доступ:** административный обход проектных ограничений не соответствует оформляемым полномочиям 2.2. Модель проектного доступа нельзя переносить без переработки; нет API деактивации/сброса пароля и полного управления жизненным циклом доступа.
- **Высокий, целостность истории:** main.py:437–445 обновляет completed_at при любом PATCH с status=done, даже без перехода; форма app.js:175–180 отправляет статус при обычном редактировании. История пишет лишь fields, без значений переходов. Дата завершения может сместиться, аналитика повторных закрытий недостоверна.
- **Высокий, выход и локальные данные:** app.js:28, 258 скрывает приложение, но не очищает tasks/projects и DOM карточки; при сетевой ошибке logout исключение подавлено и серверная cookie-сессия может остаться действующей. Возможен остаточный показ данных; требуется отдельная проверка смены пользователя/истечения сессии.
- **Высокий, полнота данных:** main.py:396 ограничивает выдачу 2000 без пагинации; app.js:40–68 считает показатели по этой выборке. Более старые задачи не попадут в представления и счётчики; F25 требует 5000 задач.
- **Высокий, повторная отправка:** создание всегда выдаёт новый UUID; в submit нет блокировки повторного нажатия и серверной идемпотентности (main.py:408–420; app.js:175–182). Возможны дубли, особенно при потере ответа; F35 не обеспечен.
- **Средний, валидация:** TaskPatch допускает явный null для обязательных title/status/priority/description, который передаётся в NOT NULL-поля БД (main.py:226–247, 430–441); ожидаем риск необработанного IntegrityError/500 вместо 422. Не воспроизводилось запуском.
- **Средний, защита входа:** failed_logins хранится только в памяти процесса, ключ использует не полностью нормализованный логин; рестарт/несколько workers/варианты пробелов ослабляют ограничение, число ключей не ограничено (main.py:262–277).
- **Средний, обновление клиента:** service-worker.js:1–11 использует постоянный cache key и cache-first assets; изменение app.js без изменения SW может оставить старый клиент. Нужны версия кэша и согласованное обновление. Нет автоматического перечитывания после восстановления сети.
- **Средний, воспроизводимость и документация:** диапазоны пакетов не зафиксированы; нет lock/SBOM/LICENSE и проверки транзитивных лицензий/уязвимостей. Старые инструкции ссылаются на 1.4 и выбор Django/React; надпись «Рабочие данные защищены» в index.html:48 не подтверждена эксплуатационной проверкой.

**Переиспользовать после проверки:** каркас FastAPI/SQLAlchemy, примитивы Argon2/CSRF/сессий, механизм task.version/409, комментарии, экранирование HTML/CSV, HTML/CSS и базовые представления, пять тестовых сценариев как регрессионные заготовки. **Адаптировать:** модели/права, API, историю, формы, жизненный цикл проектов/пользователей, синхронизацию и PWA. **Создать отдельно:** отсутствующие модули 2.2, миграции, backup/restore и релизные метаданные. Подтверждённых работающих сценариев этой сессии нет; сохранение поведения следует доказать тестами на последующем разрешённом этапе.
